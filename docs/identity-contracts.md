# Identity event contracts

Users owns identity; consumers own their local projections. Each repository carries its own copy of these types under namespace `FCG.Contracts`. There is no shared runtime project or database import. The three CLR types are distinct: `UserCreatedEvent` is the registration fact, `UserStateChangedEvent` is a complete changed state, and `UserStateSnapshotEvent` is recovery of state only. Future MassTransit default message URNs are `urn:message:FCG.Contracts:UserCreatedEvent`, `urn:message:FCG.Contracts:UserStateChangedEvent` and `urn:message:FCG.Contracts:UserStateSnapshotEvent`. Transport and topology are not connected in this increment.

All three payloads carry `eventId`, `userId`, `eventVersion`, `occurredAtUtc`, `createdAtUtc`, `name`, `email`, `role`, `state`. Identifiers are nonempty GUIDs. `eventVersion` is a positive Int64 logical version, durable and monotonic per user, advanced with a real snapshot change. It is independent of an HTTP concurrency token or PostgreSQL xmin. Registration is active v1; changed state starts at v2. `createdAtUtc` preserves the registration instant, equals `occurredAtUtc` for registration and never exceeds occurrence. UTC timestamps use exactly six fractional digits and Z; producers must reject or deliberately truncate their clock before creating a snapshot, never silently truncate incoming data. Contact is trimmed; email is lowercase, at most 256 characters, and must be a single address accepted by .NET MailAddress with Address exactly equal to the supplied value, matching the inherited registration rule. Single-label domains and quoted local parts are valid; display names and surrounding angle brackets are not canonical event addresses. Normalization is required before publication, never silently applied to incoming events; roles are exactly `User` and `Administrator`, states exactly `Active`, `Blocked`, `Deleted`.

Use `IdentityContractJson.Read<T>` / `Write<T>` as the explicit boundary codec. It enforces camelCase, all members required, unknown and duplicate members rejected, named enums, UTC microseconds and payload validation. A transport adapter must preserve these same options; default framework serialization by itself is not claimed to be configured. No password, hash, access token or key belongs in the payload. Diagnostics should identify event/user/version without logging full payload or contact.

`IdentityProjectionPolicy` is a pure decision: absent local state or greater valid version applies; older versions are ignored; same equivalent version is ignored; same divergent version conflicts; deleted state cannot be restored by a greater version. Catalog compares user/version/state/role, Notifications additionally name/email; event ID, emission time and fact/recovery type do not define equivalence. A consumer must enforce compare-and-write atomically with its own database and record its local processing result. This library does not persist projections, enforce SQL concurrency, run retries, publish outbox messages or establish broker fanout.

Registration and state are independent facts. A delayed `UserCreatedEvent` may still create one durable welcome intent even if its v1 state is ignored behind v3. A recovery snapshot never creates welcome or reconstructs lost notification intents. Recovery is an explicit Users-owned operation using the durable publication path, not a cross-service query. Deleted is terminal; blocked can be unblocked. Retain contact even for deleted users so accepted orders can finish their simulated notifications.

Notifications fixes coherent name/email/version when an intent becomes Ready. Ready retries retain that recipient; PendingContact has no invented recipient and is revisited by a recoverable local loop, including after restart and contact-arrival races. Default `Notifications:PendingContactRetryInterval` is `00:00:01`. One logical intent does not promise exactly one console line: a crash between console output and completion can repeat the line. No real email is sent. These persistence and dispatch behaviors are requirements for later increments, not implemented by this contract library.

Literal fixtures under the existing test project's `IdentityContracts/Fixtures` are independently checked into each service. Tests roundtrip each fact/recovery payload and reject invalid boundary cases. Run the repository's locked restore, Release build and full test suite documented in its main README. Tests prove contracts and pure decisions only; they do not prove authentication HTTP, token signing, broker delivery, outbox atomicity or projection persistence.
